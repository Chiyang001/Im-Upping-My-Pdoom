# v15 新增语义动画审查 / v16 修复依据

审查范围：只读检查 `v15/render.py`、`semantic_score.py`、`semantic_geometry.py`、`transformer_geometry.py`，未改生产文件、未运行 GPU 或 Git。以下行号均针对 v15。

## 核心问题

1. 新红线不是装置上的信息流，而是独立横扫。`draw_red_path`（779–785）硬设 `text_role=1`、2 px、默认高 gain，既绕过场景章节配色又绕过歌词附近的压暗区。加法混合使它比装置更刺眼，于是更像最上层绘画，损伤空间融合。
2. `semantic_host`（1006–1014）只在参考帧建立一次，**不是逐帧 billboard**，但它仍把几乎每个语义装置按同样的参考镜头逆矩阵摆在前方约 20 单位、相似比例。装置彼此未接到场景节点、路轨、机架上，造成连续的“独立展板”观感。
3. 语义存在即整体压暗：普通意义背景降至 58%，hero 降至 18%；hero 的旧环境额外乘 .08、近场骨架 .02（1168、1203、1236）。于是新几何看似浮在自己单独的空间，即使顶点本身为 3D 线框。
4. GPU 和算力的场景用同一 `flops_towers` / `flops_gates` 模板。GPU 再放四个 `moon_chip`；该网格实际是 NVDA 上月球时用的芯片火箭，带落架和红焰，放在机架顶部无法解释，也与精密工业构件风格不符。圆圈 gate 和重复小方芯片同样偏图标阵列。

## 推荐的最小可靠修复

- 删除 `sparks`、`shinigami` 新 semantic cues，恢复 v14 的原节点和单眼球；不仅删 `eye_shell` draw，还必须恢复原环境曝光，否则会得到变暗版单眼。
- GPU 改成原环境里的真实机架板卡、散热鳍片、沿地轨/竖梁固定接线。细节密度可高，但每块芯片不要有月球火箭的轮廓。算力镜头可沿相同工业语汇往深处延伸。
- 新线条应走场景角色（`text_role=0`）并有语义局部曝光，而非直接借用歌词级 `draw_red_path`。如暂时不改通用 helper，新增 semantic 专用 draw，不能破坏既有 P(doom) 能量轨迹和长尾穿越。
- 使用 clamp/ease 的有限事件进度：`p=ease((t-event_start)/event_duration)`；传播完成保留低亮固定接线，物理 topology 不平移。不要用取余制造持续运动；不要用全局 t 的正弦切换不同场景的相位。
- 语义宿主优先 `node_matrix(line_index,t) @ authored_local_pose`，或直接作为原 apparatus 的 child；显著的前景场景如 Transformer 可保留已有固定 host，但补一组固定支架把它与既有梁柱/道路相接，避免同时彻底压暗环境。
- 避免为“融合”逐帧朝向镜头；固定世界宿主可以在镜头穿过后自然离开，后续节点负责接续。
- 保持固定线宽、降低 ACC 使用面积，青色与白色负责构件，红色只负责风险、目标、有限传播或具体故障。各场景不应都有同一根醒目红线。
