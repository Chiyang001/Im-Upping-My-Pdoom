# v16 风格审查：让语义回到同一个三维世界

审查范围：只读检查 v15 新增几何与动画代码，直接从最终编码的 v14、v15 MP4 各抽取 16 帧对照，并查看已有的 v15 44 帧语义联系图。未运行 GPU、未改渲染器、未更改 Git。对照图为 `style_comparison.jpg`，保留 32 张 1080p 解码原帧 `audit_v14_*.jpg` / `audit_v15_*.jpg`。

## 结论

用户指出的问题成立。v15 许多新增对象虽然拥有细线与几何厚度，整体轮廓仍像正面芯片图标、流程图或 HUD。它们从近似相同的正面参考视角挂在原场景前方，缺少支架、空间接触与深度上的连接；又压低了旧环境，使新图标看起来像独立的一层。问题不能靠增加细节数量解决。

最明显的三个例子：

- 3.7 / 34.9 / 37.6 秒：双眼轮廓与原来的单眼球叠加，两个独立瞳孔和两只钟表改变了原有辨识度。恢复 v14 单眼球，不保留双眼装饰，也不额外补钟表。
- 119.7 秒：四枚相同的正面芯片沿画面上沿排列，下接红粉色斜脚，左右还有两条过亮算力塔，像悬浮图标。v14 这里的包围式阵列反而更有体积、尺度与环境感。删除四枚 `moon_chip` 复用图标及重复悬空红脚，将 GPU 作为斜置、相互连接的实体机架部件；前中远错位，避免整齐的一排正视图。
- 多处红色线条没有与几何动作建立因果。`circuits/stable` 的 `phase = t * speed % 1` 与 Transformer 四条循环横扫尤其明显。原本贯穿全片的 witness 已经是一条连贯红线，新扫线重复承担同一视觉角色，且像前景激光。删除独立扫线比换成更多曲线有效。

## 动态复核建议

静帧无法证明循环已消除，最终编码还需连续看 5.6–9.1、36.0–38.2、109.4–115.0、118.65–120.18 和 122.54–124.04。判断标准不是“更满”，而是一个主体、一个可追踪动作、与下一幕有真实连接；三层远近结构不必同时抢亮。

这是一轮视觉一致性修复。不要为了恢复密度再叠加更多卡片、小圆圈和无源线条；新物件的安装方式、空间遮挡、粗细层级和动作目的比数量更重要。
